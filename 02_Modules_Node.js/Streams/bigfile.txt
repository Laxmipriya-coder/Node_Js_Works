Good question! Let's understand why req.body is not supported automatically in Node.js.

1. What is req in Node.js?
When you write:

const server = http.createServer((req, res) => {
    console.log(req);
});

Node.js provides two objects:

req – IncomingMessage object (contains information about the client's request).

res – ServerResponse object (used to send a response to the client).

The important thing is that Node.js HTTP module provides the raw request data, not the parsed request body.

2. Why doesn't Node.js automatically provide req.body?
Because Node.js's built-in HTTP module is a low-level module.

When a client sends JSON data:

{
    "name": "Laptop",
    "price": 50000
}

Node.js receives this data as a stream of Buffer chunks.

It doesn't automatically know whether the incoming data is:

JSON

Plain text

Form data

XML

So, Node.js leaves the responsibility of reading and parsing the data to the developer.

3. How does Express.js solve this?
Express.js provides middleware to handle this automatically.

const express = require('express');
const app = express();

app.use(express.json());

app.post('/addproduct', (req, res) => {
    console.log(req.body);
    res.send("Product Added Successfully");
});

app.listen(8090);

Here:

app.use(express.json());

This middleware:

Reads incoming request data.

Parses the JSON data.

Stores the parsed object in req.body.

4. Understand the difference
Node.js HTTP module

Client sends JSON

Raw request stream

You read data using data and end

You parse using JSON.parse()

Express.js

Client sends JSON

express.json() middleware

Parsed data available in req.body

Interview answer
Why doesn't Node.js support req.body automatically?

"Node.js HTTP module is a low-level module. It receives request data as a stream. It does not automatically parse the incoming data into JSON or other formats. We need to manually read and parse the request body. Express.js provides middleware like express.json() to handle this automatically."

Remember: Express.js doesn't change how HTTP works. It simply makes handling HTTP requests easier.

in node.js how to overcome that
In Node.js, you can overcome this by manually reading and parsing the request body or by creating your own body-parsing function.

Since you are using the built-in http module, let's use the first approach.

1. Manually read request body
else if (req.method === "POST" && req.url === "/addproduct") {

    let body = "";

    req.on("data", (chunk) => {
        body += chunk;
    });

    req.on("end", () => {
        const product = JSON.parse(body);

        console.log(product);

        res.writeHead(200, { "Content-Type": "text/plain" });
        res.end("Product Added Successfully");
    });

}

2. Create a reusable body parser function
If you have multiple POST or PUT APIs, you don't need to write the same code repeatedly.

function getBody(req) {
    return new Promise((resolve, reject) => {

        let body = "";

        req.on("data", (chunk) => {
            body += chunk.toString();
        });

        req.on("end", () => {
            try {
                resolve(JSON.parse(body));
            } catch (error) {
                reject(error);
            }
        });

        req.on("error", reject);
    });
}

Now use it inside your server:

else if (req.method === "POST" && req.url === "/addproduct") {

    try {
        const product = await getBody(req);

        console.log(product);

        res.end("Product Added Successfully");

    } catch (error) {
        res.writeHead(400);
        res.end("Invalid JSON Data");
    }

}

what is this
req.on("data") and req.on("end") are Event Listeners in Node.js. They help us receive data sent by the client (Postman or frontend).

Let's understand them simply.

1. req.on("data")
It receives the incoming data in small pieces called chunks.

req.on("data", (chunk) => {
    console.log(chunk);
});

data – Event name.

chunk – A small piece of incoming data.

2. req.on("end")
It executes when all the request data has been received.

req.on("end", () => {
    console.log("All data received");
});

3. How do they work together?
Client (Postman)

Sends product data

req.on("data")

Receives data chunks

req.on("end")

All data received

Process the complete data

4. Simple real-life example
Imagine you are receiving a parcel containing 3 boxes.

data event: You receive each box one by one.

end event: You know all 3 boxes have arrived.

Remember for interviews
Data event: Triggered when a chunk of request data arrives.

End event: Triggered when all request data has been received.

These are called Stream Events in Node.js.

events module in node js
Events Module in Node.js
The Events module in Node.js is a built-in module used to create, handle and manage events.

In simple words, an event is an action that happens in a program. When that action occurs, we can execute a particular function.

Real-life examples:

Clicking a button.

Receiving a message.

A user logging in.

A file being opened.

1. How to use Events module?
First, import the events module.

const EventEmitter = require('events');

const event = new EventEmitter();

events – Built-in Node.js module.

EventEmitter – Class used to create and manage events.

event – Object used to trigger and listen to events.

2. Important methods
There are three important methods:

Method

Purpose

on()

Listen to an event

emit()

Trigger an event

once()

Execute an event only once

3. Example using on() and emit()
const EventEmitter = require('events');

const event = new EventEmitter();

// Create event listener
event.on('welcome', () => {
    console.log("Welcome to Node.js");
});

// Trigger event
event.emit('welcome');

Output:

Welcome to Node.js
Explanation:

event.on() listens for the welcome event.

event.emit() triggers the welcome event.

When the event is triggered, the callback function executes.

4. Example using once()
const EventEmitter = require('events');

const event = new EventEmitter();

event.once('login', () => {
    console.log("User Logged In");
});

event.emit('login');
event.emit('login');

Output:

User Logged In
Why only once? Because once() executes the callback only the first time the event is triggered.

5. Passing arguments to events

const event = new EventEmitter();

    console.log(name);
    console.log(age);

Laxmipriya
